## 疑似同源病例组

文件名审计只把首个连字符之前的部分作为疑似组 ID，例如 `1379-L12`、`1379-R5` 会被归入 `1379`。这只是保守的警告规则，不能证明这些记录来自同一患者。

### 恶性数据源

在 `metadata.csv` 的真实恶性数据源中发现 2 个跨 split 疑似组：

| 疑似组 | 病例 ID | split | 标签 |
| --- | --- | --- | --- |
| 503 | 503-L1、503-L10 | train、val | 3 |
| 624 | 624-R7、624-R8 | train、val | 2 |

这两组均未涉及恶性测试集，因此没有发现基于当前前缀规则的恶性测试跨 split 疑似组。

### 良性数据源

`metadata_5class.csv` 中的良性记录共 274 条，其中发现 22 个跨 split 疑似组；其中 13 组涉及良性测试集，共涉及 15/42 个良性测试 ID。由于现有 CSV 和 `label_new.xlsx` 都没有患者 ID、检查 ID 或明确的病灶分组字段，当前不能判定这些组是同一患者的多病灶/双侧检查，还是不同病例恰好共享数字前缀。

这项风险主要影响良恶性二分类和端到端五分类的泛化评估，不直接改变本次 82 例恶性条件四分类审计的标签与模态核查结论。应在论文中避免把当前划分描述为已经完成患者级去重，除非从数据提供方获得患者级分组信息。

### 关于 `split_manifest.json` 的解释

当前 manifest 的疑似组是由 `train`、`malignant_val`、`malignant_test`、`binary_val` 和 `binary_test` 等逻辑视图拼接生成的。后二者包含前面恶性验证/测试病例的重复视图，因此 manifest 中部分病例 ID 重复属于清单构造现象，不能直接当作真实跨 split 泄漏。真实划分审计应基于原始元数据和互斥的来源样本集合完成。

## 对后续实验的影响

1. 在没有患者级 ID 前，不建议先修改恶性 82 例的测试标签或重新解释其错误病例。
2. 在论文主结果中，继续把恶性条件四分类作为主要诊断指标；二分类 AUC 和端到端五分类结果需要注明良性数据存在待确认的同源组风险。
3. 若数据提供方能够补充患者级分组，应先按患者级分组重新生成训练/验证/测试清单，再复现实验；若无法补充，则至少增加“按前缀组隔离”的敏感性分析。
4. 在当前固定 B1 切分上，可以继续做 BUS-only、BUS+SWE、BUS+CDFI、BUS+文本和完整四模态消融，因为 82 例恶性测试病例的模态文件和标签链路已通过基础审计。
