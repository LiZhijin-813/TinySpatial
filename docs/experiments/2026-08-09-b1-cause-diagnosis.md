# 2026-08-09 B1 原因诊断（BUS+Text，阶段 B）

## 结论先行

当前证据支持的判断是：**TNBC=0 的主要原因不是单一模态缺失，也不是当前已核对到的数据链路错误，而是少数类学习、类别边界塑形与 checkpoint 选择策略之间存在耦合。** 数据问题暂时不是首要解释，但跨前缀 split 风险仍需在论文和后续实验里保留说明。

## 诊断范围

本页只整理截至 `2026-08-09` 已核对的信息，用于解释阶段 B 中 `BUS+Text` 单 seed=`42` 训练为什么仍会出现 TNBC 召回不稳定甚至为零的现象。

本页不新增实验，不访问实验服务器，不重跑训练，也不把任何一次诊断结果表述为“问题已经解决”。

## 已核对事实

### 1. A0 数据审计没有支持“数据链路直接导致 TNBC=0”

已核对的 A0 事实如下：

- canonical malignant train/val/test=`534/151/82`
- TNBC train/val/test=`79/22/13`
- 13 个 TNBC 测试病例四种模态均存在且对齐
- 文本字段非空
- 未发现明显标签词泄漏
- 未发现完整 `case_id` 的重复病例

因此，当前没有证据把 TNBC=0 直接归因于“TNBC 测试样本缺模态”“文本为空”“标签错位”或“显式标签泄漏”。

### 2. 数据问题仍不是零风险，但目前不是首要解释

A0 同时发现：

- 以前缀规则审计时，`503` 与 `624` 存在跨 split 风险；
- 这类风险应继续保留在论文和后续实验说明中；
- 但它**没有解释**为什么 `BUS+Text` 在当前设置下会出现 TNBC=0。

因此，数据问题当前更像是**需要持续披露的背景风险**，而不是本轮原因诊断里的第一解释。

## BUS+Text seed=42 重平衡诊断结果

下表汇总四组已核对设置。类别顺序均为 `[Luminal A, Luminal B, HER2+, TNBC]`。

| weighting | sampler | Macro-F1 | Balanced Accuracy | 关键现象 | 预测分布 |
| --- | --- | ---: | ---: | --- | --- |
| `inverse` | `none` | 0.233168 | 0.257841 | TNBC recall=`0` | `[31,20,20,11]` |
| `inverse` | `balanced` | 0.200583 | 0.258440 | TNBC recall=`0.461538`，但 HER2+ recall=`0` | `[7,33,0,42]` |
| `none` | `none` | 0.203153 | 0.281362 | TNBC recall=`0`，HER2+ recall=`0.903226` | `[16,0,66,0]` |
| `none` | `balanced` | 0.220442 | 0.210784 | 四类召回均非零，TNBC recall=`0.230769` | `[11,34,20,17]` |

## 诊断解释

### 1. 重平衡会明显改写决策边界，而不是只做温和校正

从 `inverse + none` 到 `inverse + balanced`，TNBC recall 从 `0` 升到 `0.461538`，说明 balanced sampler 的确能把模型从“几乎不愿意判 TNBC”推到“愿意输出更多 TNBC”。但代价同样明显：HER2+ recall 直接掉到 `0`，预测分布也从 `[31,20,20,11]` 变成 `[7,33,0,42]`。这不是局部微调，而是决策边界被显著改写。

这说明当前问题不是“模型永远学不会 TNBC”，而是**一旦尝试救回 TNBC，边界会明显挤压其他类别，尤其是 HER2+**。

### 2. 取消 weighting 并不能单独救回 TNBC

从 `inverse + none` 切到 `none + none` 后，Balanced Accuracy 从 `0.257841` 升到 `0.281362`，HER2+ recall 也达到 `0.903226`，但 TNBC recall 仍然是 `0`，并且预测分布收缩为 `[16,0,66,0]`。

这说明仅仅取消 loss weighting，并不会自动恢复 TNBC 的可分性；它更像是让模型进一步偏向当前更稳定、数量更占优的类别边界。

因此，**“TNBC=0 是 inverse weighting 单独造成的”这个解释不成立。**

### 3. `weighting none + sampler balanced` 让四类都有预测，但整体更差

`none + balanced` 是四组里唯一一个“四类召回都非零”的设置，TNBC recall=`0.230769`，预测分布为 `[11,34,20,17]`。这说明 balanced sampler 在没有 weighting 干预时，确实能缓解类别塌缩。

但它的 Macro-F1=`0.220442`、Balanced Accuracy=`0.210784`，整体并没有优于当前 `inverse + none` 基线，也不能被当作正式提升。它更像是一个诊断信号：**只要强行拉回少数类，整体边界就会重新分配，但当前分配方式还不稳定。**

### 4. 主要矛盾落在“少数类学习 + checkpoint 选择”耦合，而不是模态缺失

综合 A0 与这四组 BUS+Text 诊断，可得到更稳妥的解释：

1. 当前没有证据支持“单一模态缺失”是 TNBC=0 的主因。
2. 数据链路核查没有发现足以直接解释 TNBC=0 的错误。
3. 不同 weighting/sampler 组合会显著改变类别边界，尤其体现在 TNBC 与 HER2+ 之间的取舍。
4. 因为阶段 B 当前仍采用既有 checkpoint 选择策略，少数类学习效果会与“哪一轮被选为 best”耦合在一起。

因此，现阶段更合理的主因判断是：**BUS+Text 已经具备一定的 TNBC 可学习信号，但这部分信号在现有重平衡与 checkpoint 选择机制下不稳定，容易在最佳轮次选择时被主流类别表现覆盖。**

## 当前不能下的结论

以下说法当前都不成立：

- 不能宣称“TNBC 已经被解决”；
- 不能把 `balanced` 结果当作正式提升；
- 不能把问题简单归因为“文本没用”或“缺某个模态”；
- 不能把跨前缀 split 风险当作已经排除；
- 不能把本页结论外推成所有模态组合都成立的规律。

## 下一步建议

下一步先固定 `BUS+Text`，优先做两件事：

1. 比较更稳定的损失设计，例如 stable loss 或 logit-adjusted CE，与当前重平衡策略的差异；
2. 审计 checkpoint 选择策略，确认当前 `best` 轮次是否系统性偏向多数类表现，而压低了 TNBC 保留。

在这两步完成前，不应把任何一次 balanced 采样得到的 TNBC 回升写成正式实验提升；它目前只能作为“边界可被推动，但代价和稳定性都还未解决”的诊断证据。

## 现阶段工作结论

基于现有证据，阶段 B 中 `BUS+Text` 的 TNBC 异常更接近**少数类优化失败与模型选择机制共同作用**，而不是单一模态缺失或已核对数据链路错误。数据审计已经把“明显缺模态/错标签/空文本”这类直接解释基本排除，但跨前缀 split 风险仍应继续披露，不宜从文档中删除。
