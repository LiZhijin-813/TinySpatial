## 置信度观察

审计报告以条件四分类置信度 0.80 作为高置信度错分阈值。本次没有达到该阈值的错误病例。结合预测分布塌缩到 HER2+、Luminal B 与 TNBC 召回为零的现象，当前更像是模型没有形成足够有区分度的亚型表示或决策边界，而不是少量高置信度异常病例主导了整体指标。

该判断是诊断性推断，不能替代标签审查、模态质量检查和消融实验。

## 当前结论

1. B1 的二分类能力较好，但恶性四分类出现明显类别塌缩，说明“能识别恶性”不能推出“能完成分子分型”。
2. 当前失败不是单纯由少数高置信度错分病例造成，主要问题是 Luminal B 和 TNBC 未形成可用的稳定决策边界。
3. 病例级审计链路已经能够在固定切分上复现基线并输出可人工核查的病例清单，因此后续可以围绕病例和模态开展针对性实验。

## 下一步实验顺序

1. **先核查病例与标签**：针对 48 个亚型错分病例，优先检查标签来源、病例 ID 映射、四类标签编码和重复病例；对 `034`、`1237`、`395` 额外检查恶性标签与端到端良性预测是否存在数据链路异常。核查只做记录，不自动改标签。
2. **核查模态可用性**：利用 `case_predictions.csv` 中的 BUS、SWE、CDFI 和文本存在性字段，比较正确病例、亚型错分病例和恶性到良性病例的模态缺失分布。
3. **固定 B1 做单变量消融**：分别评估 BUS-only、BUS+SWE、BUS+CDFI、BUS+文本以及完整四模态，判断性能塌缩是否由某一模态、文本分支或模态缺失处理触发。
4. **再处理类别不平衡**：在确认标签和模态链路无误后，再比较类别权重、logit adjustment、分阶段分类器或受约束的采样策略；每次只改变一个训练变量，并继续使用恶性条件 Macro-F1、四类召回率和预测分布作为主判据。
5. **暂不扩大模型结构**：在病例与模态审计完成前，不继续叠加新的跨模态融合模块，避免把数据链路问题误判为网络结构问题。

训练阶段的 `metrics_test.json` 使用“测试分区—指标”的嵌套结构，例如 `malignant.malignant`。审计汇总原先只支持直接传入四分类指标，导致真实 B1 运行在指标复现阶段失败。现已增加兼容逻辑，并用直接指标格式和嵌套指标格式完成回归测试；本地病例审计测试结果为 `28 passed`。
