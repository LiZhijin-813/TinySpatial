# 数据质量与模型证据审计设计

## 目标

在继续修改模型之前，区分当前四分类分型效果不理想究竟主要来自：

1. 标签、类别分布或文本报告存在系统性问题；
2. 模态缺失、图像质量或 BUS-SWE 空间对应关系不稳定；
3. 模型依赖文本捷径、背景信息或不稳定的图像区域；
4. 当前融合和训练目标放大了上述数据问题。

本阶段只做诊断，不重新训练模型，不修改标签，不把审计结果直接当作正式性能结论。

## 已知证据

当前结果表明：

- `Luminal B` 和 `TNBC` 在多个训练种子下出现零召回或极低召回；
- 同协议全模态相对 `BUS+Text` 的 LA/LB 探针提升为 `0.0286`，接近但未达到预设门槛；
- 文本屏蔽会明显改变固定检查点的预测，而 CDFI 屏蔽影响较小；
- 不同训练种子下的 `bus-text` 结果波动明显；
- 当前数据没有可直接使用的 ROI 或病灶裁剪。

这些证据说明数据质量和模型设计都可能参与造成失败，不能在审计前单独归因于某一方。

## 总体方案

采用两个只读审计任务，顺序执行：

1. 病例、标签和文本审计：先确认输入与监督信号是否可信；
2. 模型证据审计：在数据审计结果可解释的前提下，检查模型依赖的空间区域与模态证据。

不在本阶段运行新的深度训练，不增加模态组合，不修改现有模型结构。

## 任务一：病例、标签和文本审计

### 输入

- 项目中的 `metadata.csv`、固定切分清单和病例组信息；
- BUS、SWE、CDFI 图像文件；
- 临床文本 JSON；
- 现有病例级预测、错误审计和模态消融结果；
- 重点病例集合：`Luminal B`、`TNBC` 低召回病例，以及已有 82 例恶性测试审计病例。

### 检查内容

#### 标签与病例组

- 统计四类标签数量、训练/验证/测试分布和每折分布；
- 检查重复病例、疑似同源病例和病例组跨切分情况；
- 检查同一病例是否存在多条相互冲突的标签记录；
- 标记少数类样本过少、某折缺失类别和异常标签值。

#### 模态完整性与图像质量

- 统计每种模态缺失率；
- 检查文件是否可读取、尺寸是否异常、图像是否为空白或近似常量；
- 记录 BUS 与 SWE 的原始尺寸、长宽比和导出规格差异；
- 统计 CDFI 彩色信息是否存在，避免大量图像退化为灰度或无血流图。

#### 文本风险

- 统计空文本、文本长度、重复模板和高频固定短语；
- 检查文本是否直接出现 `Luminal A`、`Luminal B`、`HER2`、`TNBC` 或等价诊断提示；
- 检查这些关键词与标签的一致性，标记“文本提示与标签冲突”的病例；
- 记录文本是否可能包含病理结果、术后诊断或其他接近目标标签的信息。

审计程序只生成风险标记，不自动修改标签，也不将文本关键词出现直接判定为标签错误。

### 输出

- 全体病例统计 JSON；
- 脱敏病例级 CSV，使用病例 ID、标签、风险标记和模态完整性字段；
- 中文 Markdown 审计报告，汇总标签分布、缺失率、文本风险和重点病例列表；
- 原始文本和未脱敏片段只保存在远端 `/data`，不写入 Git。

## 任务二：模型证据审计

### 输入

- 同协议 `BUS+Text` 和 `Full` 检查点；
- 相同病例组五折探针清单；
- 现有 82 例病例级预测与错误审计；
- 任务一输出的文本风险和模态质量标记。

### 检查内容

#### 模态扰动一致性

- 对同一病例分别使用完整输入、屏蔽 SWE、屏蔽 CDFI、屏蔽 Text；
- 记录五分类预测、恶性条件四分类预测、置信度变化和错误类型变化；
- 分别统计整体、Luminal B、TNBC 和重点错误病例的变化；
- 区分“改变预测但改善结果”和“改变预测但造成坍缩”两种情况。

#### 空间证据稳定性

- 对 BUS、SWE、CDFI 计算轻量梯度显著性或输入遮挡敏感性；
- 只记录归一化后的空间集中度、中心区域与边缘区域响应比例、不同模态之间的空间相似度；
- 对重点错误病例和少量正确病例进行可视化抽样；
- 在没有 ROI 的前提下，不把中心区域高响应等同于真实病灶定位，只作为背景依赖和空间稳定性的诊断信号。

#### 文本依赖性

- 对含有目标关键词、疑似模板文本和普通文本分别统计预测变化；
- 对文本截断、关键词遮蔽后的输出进行对照；
- 若文本遮蔽导致某一类别预测大规模坍缩，标记为文本捷径风险，而不是直接宣布文本泄漏。

### 输出

- 每病例审计 CSV，包含预测变化、模态扰动变化、空间集中度和文本风险标记；
- 汇总 JSON，包含各类别、各错误类型和各模态的统计；
- 少量重点病例的显著性图或遮挡图，保存到远端 `/data`；
- 中文模型证据审计报告，不写入原始文本和大体积中间特征。

## 判定规则

- 若发现标签冲突、跨切分重复或明显标签缺失，优先处理数据协议，不继续调整模型结构；
- 若文本包含高比例直接分型提示，优先处理文本去泄漏和文本使用边界；
- 若标签和文本基本可靠，但图像响应分散或明显集中于边缘/设备区域，优先处理 ROI-Free 的空间建模和模态对齐；
- 若输入证据基本稳定但不同种子仍大幅波动，优先处理类别不平衡、选模指标和训练目标；
- 若不同模态在同一病例上给出相互冲突的证据，不追加模态组合，优先分析融合门控和模态质量筛选。

审计结果只用于确定下一阶段方向，不直接修改标签或宣称模型已解决某类错误。

## 隐私与存储约束

- 原始文本只在远端 `/data` 临时读取和审计；
- Git 中只提交脱敏统计、病例级风险标记和中文结论；
- 不提交权重、缓存、原始文本、完整显著性张量或训练日志；
- 所有输出使用固定提交哈希、检查点路径和数据版本记录，保证审计可复现。

## 计算约束

- 任务一只做一次全量自动统计和一次重点病例汇总；
- 任务二只使用已有检查点，不进行训练；
- 只对重点错误病例和少量正确病例生成可视化，不生成全量图像；
- 任一审计发现高置信度数据协议问题时立即停止后续模型审计，先记录问题。
