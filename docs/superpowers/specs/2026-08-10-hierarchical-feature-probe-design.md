# 病例组五折层级特征探针诊断设计

## 目标

在不重新训练深度模型的前提下，定位四分类分型失败发生在哪个决策层级。诊断必须沿用现有病例组约束五折清单，并且每一折只能使用训练折拟合轻量分类器，避免把测试折信息泄漏到分类边界中。

本诊断用于解释当前模型和固定检查点的表示能力，不把二分类结果直接作为最终论文模型性能。

## 诊断层级

使用四分类标签约定：

- `0`：Luminal A
- `1`：Luminal B
- `2`：HER2+
- `3`：TNBC

定义三个互不混淆的二分类任务：

1. `luminal_vs_non_luminal`：Luminal A、Luminal B 为 0；HER2+、TNBC 为 1。
2. `luminal_a_vs_luminal_b`：仅保留 Luminal A 与 Luminal B，分别映射为 0 和 1。
3. `her2_vs_tnbc`：仅保留 HER2+ 与 TNBC，分别映射为 0 和 1。

这三个任务分别回答：大类边界是否存在、Luminal 内部是否可分、非 Luminal 内部是否可分。

## 数据流

1. 从已有 `flat5` 检查点加载模型和恶性病例元数据。
2. 对全部 767 个恶性病例提取一次 `fused_features`，保持病例编号顺序。
3. 读取病例组约束五折清单。
4. 对每一个诊断层级和每一折：
   - 根据该层级筛选训练折和测试折中的有效样本；
   - 仅使用训练折特征拟合二分类线性探针；
   - 在对应测试折的有效样本上预测；
   - 同时运行无权和逆频率加权两种探针。
5. 汇总每个层级五折 Macro-F1、Balanced Accuracy 的均值、标准差和逐折值。

每个层级独立筛选样本，不能把无关类别当作负类。例如 `luminal_a_vs_luminal_b` 不得使用 HER2+ 或 TNBC 样本。

## 代码边界

新增 `code/train/run_cv_hierarchical_probe.py`，负责命令行参数解析、检查点特征提取、折划分、层级任务循环和 JSON 输出。

新增的辅助函数应保持纯函数性质，优先放在该脚本中，只有在现有工具确实需要复用时才抽取到公共模块。现有 `feature_probe.py` 和 `run_cv_feature_probe.py` 的行为保持不变。

输出文件为 `hierarchical_probe_metrics.json`，至少包含：

- 协议说明、检查点路径、病例组清单路径和样本总数；
- 每个层级的有效样本数量和标签计数；
- 无权与逆频率加权的逐折指标；
- 每种方法的五折均值、标准差和逐折值；
- 每折混淆矩阵、预测分布和各类别召回率。

## 测试设计

先添加失败测试，再实现代码。测试覆盖：

- 四分类标签到三个层级标签的映射正确；
- 无关类别在层级任务中被排除，而不是错误地映射为负类；
- 标签计数缺失时能够显式报错；
- 层级指标聚合能够正确计算均值、标准差和逐折值；
- 非法标签或空筛选结果能够给出中文错误信息。

不在单元测试中加载 GPU 检查点；真实检查点提取和病例组五折运行作为远端集成诊断验证。

## 解释规则

- 若 `luminal_vs_non_luminal` 明显高于两个内部二分类，说明主要瓶颈是 Luminal A/B 或 HER2+/TNBC 的细分边界。
- 若三个层级都接近随机水平，说明固定融合表示整体缺乏稳定分型信息，继续调分类损失的收益预期较低。
- 若某个内部层级明显较好，则后续可围绕该层级设计分层分类器，但必须在独立测试集和多种子实验中复验。

本诊断结果不用于选择测试集最优超参数，也不替代正式的独立训练和最终测试协议。
